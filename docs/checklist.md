- [ ] **4. Scoring library + tests**
  Spec ref: `spec.md > Library (lib/) > lib/scoring/*`
  What to build: Implement all seven `lib/scoring/*` modules. `severity.ts` exports the `COMPONENT_SEVERITY` table (prefix-match rules: `AIR BAGS`/`FUEL SYSTEM`/`ENGINE AND ENGINE COOLING`/`STEERING`/`SERVICE BRAKES` → 2.0×; `POWER TRAIN`/`ELECTRICAL SYSTEM` → 1.5×; default 1.0×) and `severity(componentString)` walks the table in declared order. `recalls.ts` implements `subRecallScore(recalls)` = `max(0, 100 − 15 × Σ severity(r.component))`. `complaints.ts` implements `subComplaintsScore(count)` = `max(0, 100 − 20 × log10(count + 1))`. `safety.ts` implements `subSafetyScore(stars)` = `stars × 20` for `stars ∈ [1..5]`, else `null`. `emissions.ts` implements `subEmissionsScore(year)` per the v0 lookup (≥2017→100, 2004–2016→75, 1994–2003→50, <1994→25). `ageWear.ts` implements the two-input formula `max(0, 100 − 2 × age − 0.0002 × mileage)` with mileage=0 fallback to `max(0, 100 − 3 × age)`. `composite.ts` implements `combine(subScores)` with base weights (0.25/0.15/0.25/0.20/0.15), renormalization for 1–2 unavailable sub-scores, and the 5-band letter map (≥85 A, ≥70 B, ≥55 C, ≥40 D, else F). When 3+ are unavailable, return `{composite: null, letter: null, renormalized: true}`. Write Vitest fixture tests for each module covering: representative inputs, zero, max, edge cases (negative/missing inputs), and the renormalization paths in `composite.ts`.
  Acceptance: All `tests/scoring/*.test.ts` pass. The fixture suite for `composite.ts` covers: all 5 sub-scores available (no renormalization), 1 unavailable (renormalized), 2 unavailable (renormalized), 3 unavailable (returns nulls). Hand-spot-check: `subRecallScore` for the 2007 Civic recall list (6 airbag-frontal at 2.0× + 1 brake at 2.0× + 1 fuel-tank at 2.0× + 1 brake-light at 1.0× = sum 17, score floors at 0).
  Verify: Run `npx vitest run tests/scoring/` and confirm green. From a Node REPL, import `subRecallScore` and pass an array reflecting the 2007 Civic recall set; confirm result is 0. Pass an empty array; confirm result is 100.

- [x] **5. Verdict generator + tests**

  What to build: Implement `lib/summary.ts` exporting `generateVerdict({letter, subScores, recalls})`. The algorithm: compute each available sub-score's contribution-to-grade-reduction = `(100 − value) × weight`, sort descending, name top 3 for grades C/D/F. For grades A/B, name 1–3 highest-scoring categories with positive copy. Use `severity.label` (`"airbag"`, `"fuel-system"`, etc.) for plain-English category names when the recalls sub-score drives the verdict. Implement the hedge-word linter that rejects output containing `some`, `may have`, `potentially`, `might`, `possibly` (throws in dev, falls back to a deterministic template in prod). The output must contain no exclamation marks, no all-caps words longer than 2 chars (preserve "USA" / "VW" if they appear), no scare-quoted phrases. Output must be deterministic: same input always produces the same string. Write `tests/summary.test.ts` covering: A-grade output, F-grade-with-3-failed-categories output, F-grade-with-recalls-driving + verifies recall categories appear by `severity.label`, hedge-word-linter assertion (the test passes a synthetic input designed to almost-trigger a hedge word and asserts the output contains none), determinism assertion (same input → same string twice), voice-policy assertions (no `!`, no all-caps words >2 chars, no scare-quote pairs).
  Acceptance: `tests/summary.test.ts` is green. Manually invoking `generateVerdict` for a 2007-Civic-shaped fixture produces a string mentioning "airbag" and committing language ("multiple unrepaired airbag inflator recalls" or similar — not "some" / "may have").
  Verify: Run `npx vitest run tests/summary.test.ts` and confirm green. From a Node REPL, generate a verdict for a 2007-Civic-shaped fixture; eyeball the output for tone (factual, calm, names "airbag" by category, no hedge words, no exclamation).
